# OBS-0001 — Read-only combat feedback metadata

## Request and scope
The user requested distinct attack/skill visual effects rather than a brief line. The lead approved a narrowly observational Core extension after the VFX contract identified missing attribution. This is **not a new skill or combat-rule implementation**. It supplies accurate outputs for an adapter; it does not itself draw a VFX, play audio, delay damage or add a dodge window.

Design: [ADR-0011](../architecture/ADR-0011-read-only-combat-observation.md). Baseline is published UX0004 f4aa1e45. This isolated implementation does not merge UX0005 runtime presentation or mobile/UI work.

## Implemented boundary
- Existing GameEvent gets explicit FeedbackMechanism metadata; old constructor and fields keep their semantics. Unknown is the fallback. Original event enum values, buffer count/order and drop-newest behavior remain unchanged.
- Independent fixed 512 notifications cover actual support heal (including zero delta at full health), actual buff duration refresh, and qualified wall-bounce branches. They never consume old event slots or gate rules.
- Full-generation, run/wave/tick-stamped enemy movement samples report the honey multiplier actually used and the knock movement branch. They are not a prediction or post-hoc proximity calculation.
- Pause clears one-step discrete outputs but preserves a valid same-tick movement observation. Prepare/Begin/Restore clears all new transient scope; no state gets replayed from a checkpoint.
- Plain netstandard2.1 C#, no engine types, callbacks, audio, assets or gameplay-consumer dependencies. Consumers must read every Step during catchup; there is no backlog across Steps.

## Compatibility
Checkpoint schema1, catalog JSON, rules constants and Persistence source remain unchanged. New buffers are not serialized. Existing C# consumers rebuild against the added field; arbitrary native/raw binary struct ABI is not promised. An authored-source audit found no Marshal/raw serialization of GameEvent in this project.
